# Build a Premium Movie & TV Discovery Website with TMDB + OMDb + FreeKeys

Build a complete, production-structured movie and TV discovery website with an original premium cinematic design.

The website should provide functionality similar to modern streaming/movie-discovery platforms, but must use an original UI, branding, layout, copy, and components.

Do NOT copy PopcornMovies' exact design, branding, logo, proprietary assets, source code, or text.

# 2. API Architecture

Use the following data providers:

### Primary metadata source

TMDB API.

TMDB should provide:

* Movies
* TV shows
* Anime
* Trending
* Popular
* Top rated
* Genres
* Search
* Movie details
* TV details
* Seasons
* Episodes
* Cast
* Crew
* Recommendations
* Similar titles
* Images
* Release dates

### Secondary metadata source

OMDb API.

Use OMDb when useful for:

* IMDb rating
* IMDb ID
* Additional movie metadata
* Ratings
* Alternative metadata fields

### FreeKeys integration

Use the `freekeys` npm package as a development fallback for obtaining TMDB/OMDb credentials.

Repository:

https://github.com/rickylawson/freekeys

Package:

```bash
npm install freekeys
```

The package exposes credentials such as:

```text
tmdb_key
imdb_key
```

according to its documented usage.

IMPORTANT:

Do NOT expose these keys to the browser.

Do NOT put the `freekeys` package inside client components.

Do NOT call `freekeys()` from the browser.

Only access it from server-side code.

# 3. Environment Variables

Prefer manually supplied environment variables in production:

```env
TMDB_API_KEY=
OMDB_API_KEY=
TMDB_BASE_URL=https://api.themoviedb.org/3
OMDB_BASE_URL=https://www.omdbapi.com
```

Create a server-side API-key resolver:

```text
lib/api/keys.ts
```

Logic:

```text
1. Check TMDB_API_KEY.
2. Check OMDB_API_KEY.
3. If credentials are missing, optionally attempt freekeys().
4. Cache the resolved credentials.
5. Never return credentials to the client.
```

The application should work normally when valid environment variables are supplied.

FreeKeys should NOT be treated as a guaranteed production credential provider.

# 24. Rate Limit Protection

Create server-side safeguards:

* Request caching
* Deduplication
* Debounced search
* Error handling
* Retry only when appropriate
* Avoid duplicate requests
* Avoid fetching the same title repeatedly

Do not repeatedly call the free-key provider on every request.

# 25. API Failure Handling

If TMDB fails:

```text
Show a clean error state.
```

If OMDb fails:

```text
Continue using TMDB.
```

If FreeKeys fails:

```text
Use environment variables.
If no credentials exist, show a configuration error.
```

Never expose API keys in error messages.

---

# 26. Security

Critical requirements:

* API keys must remain server-side.
* Never put API keys in `NEXT_PUBLIC_*`.
* Never return API keys from Route Handlers.
* Never log API keys.
* Never expose FreeKeys output to the browser.
* Validate route parameters.
* Sanitize search input.
* Add reasonable request protection.
* Never store private credentials in Git.

Create:

```text
.env.local
```

and ensure it is included in:

```text
.gitignore
```

# 32. Final API Flow

The final architecture should be:

```text
                 USER
                   │
                   ▼
              NEXT.JS UI
                   │
                   ▼
        SERVER DATA FUNCTIONS
                   │
          ┌────────┴────────┐
          │                 │
          ▼                 ▼
        TMDB              OMDb
          │                 │
          └────────┬────────┘
                   │
                   ▼
            NORMALIZED DATA
                   │
                   ▼
             UI COMPONENTS
```

Credential resolution:

```text
Environment Variables
        │
        ├── TMDB_API_KEY
        │
        └── OMDB_API_KEY
                 │
                 ▼
        If missing credentials
                 │
                 ▼
             FreeKeys
                 │
                 ▼
        Server-side only
```

FreeKeys is a fallback mechanism, not the application's movie-data API.
